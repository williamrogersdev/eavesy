Eavesy runs a hosted [MCP](https://modelcontextprotocol.io) server at
`https://mcp.eavesy.com`. An agent that speaks MCP can search your recordings
and dictations and pull the Markdown summary and transcript into its own
context, with nothing to copy and paste.

You add it by URL. The agent sends you to Eavesy to sign in and approve the
connection, then it connects. There is no token to copy.

## Add it by URL

The server URL is the same everywhere:

```text
https://mcp.eavesy.com
```

### Claude.ai and Claude Desktop

1. Open **Settings → Connectors** and choose **Add custom connector**.
2. Name it `Eavesy` and paste `https://mcp.eavesy.com` as the URL.
3. Select **Connect**. Sign in to Eavesy and approve the connection.

If the menus have moved, follow Anthropic's guide to
[custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### ChatGPT

1. Turn on developer mode under **Settings → Apps & Connectors → Advanced**.
2. Create a connector with `https://mcp.eavesy.com` as the URL and OAuth as the
   authentication.
3. Sign in to Eavesy and approve the connection.

OpenAI moves these settings from time to time, and developer mode depends on
your plan. If you can't find them, search ChatGPT's help for "developer mode".

### Claude Code

```bash
claude mcp add --transport http eavesy https://mcp.eavesy.com
```

Then run `/mcp` in Claude Code, pick `eavesy` and authenticate. Your browser
opens the Eavesy approval page.

Or install the Eavesy plugin, which adds the same server plus a skill that
tells Claude when to look up your meetings and dictations:

```text
/plugin marketplace add williamrogersdev/eavesy
/plugin install eavesy@eavesy
```

### Other clients

Any client that supports MCP authorization (OAuth 2.1 with dynamic client
registration) can add `https://mcp.eavesy.com` by URL. Clients that can't do
OAuth can use a [pasted token](#paste-a-token-instead).

## What you approve

The approval page shows which app is asking and where you'll be sent back.
A connection is **read-only** by default: it can search and read your
recordings, dictations and action items.

If the app asks for write access, the page also shows **Also let it write**,
unchecked. Tick it only if you want the agent to make changes. Every tool
available today only reads, so this matters once write tools ship. A
read-only connection never sees write tools in its tool list, and calling one
is refused.

Every approved app is listed in **Settings → AI assistants (MCP)**, where you
can revoke it. Revoking cuts it off at once. An app you haven't used for
90 days has to be approved again.

## Paste a token instead

For clients that can't sign in with OAuth, create a token by hand:

1. Sign in to the web app and open **Settings → AI assistants (MCP)**.
2. Tick **Allow writes** only if this connection should be able to write.
3. Select **New connection**. Eavesy shows a ready-made client configuration
   once. Paste it into your agent's MCP settings.

The configuration looks like this:

```json
{
  "mcpServers": {
    "eavesy": {
      "type": "http",
      "url": "https://mcp.eavesy.com",
      "headers": { "Authorization": "Bearer YOUR_TOKEN" }
    }
  }
}
```

Tokens go in the `Authorization` header and expire 90 days after they were
last used. Older URL-path tokens (`https://mcp.eavesy.com/YOUR_TOKEN`) still
work for clients that can only be given a URL, but they are deprecated and can
be turned off on self-hosted deployments with `MCP_ALLOW_PATH_TOKENS=false`.

## Tools

| Tool | What it does |
|---|---|
| `search_library` | Retrieve source passages from completed account recordings, with segment IDs and timestamps. |
| `ask_library` | Answer from supported recording evidence when cloud answers are enabled; can abstain or report context limits. |
| `list_projects` | List the projects available to the connection. |
| `search_meetings` | Search recordings by title or transcript. Returns matches with an excerpt. |
| `get_meeting` | Get one recording by ID, with its summary and full transcript. |
| `recent_meetings` | List the most recent recordings. |
| `search_dictations` | Search your dictations. |
| `get_action_items` | List action items, filterable by status (`open`, `completed`, `all`) and owner. |

Library retrieval does not guarantee exhaustive coverage. Inspect quoted passages and retain any warnings about unanswered parts or context limits. Cloud answer availability depends on the deployment and account configuration.

These tools only read. The tool names say "meetings" because that is the name
of a recording in the data model. Recordings need to be in your account, so
recordings made on a Mac that isn't signed in are not available. Screenshots,
clipboard captures and notes from the Mac app are not available over MCP
(screenshots and images sync between your signed-in Macs, but MCP doesn't read
them). An agent with file access
can still [read them from disk](/docs/session-folder-format).

<Callout type="note">
Requests are rate limited per connection. A read-only connection can't create,
edit, or delete anything.
</Callout>

## Local media and client checks

The hosted server does not read arbitrary files from your Mac. Use an agent with local file access or attach media explicitly. Mac version 0.5.4 does not expose the newer local walkthrough MCP server.

After connecting, ask for a known recording title and inspect the result before relying on broader questions. If authorization fails, check that the client supports the configured transport and OAuth, then use the supported token setup only when necessary. Never paste a token into a public issue or a shared project file.

## Verify a connection with one known source

Ask the client for a recording with a title you recognize, then inspect its returned transcript or summary. Confirm that the source belongs to the intended account. Next ask one narrow question and open the supporting passage rather than treating a list of available tools as proof of useful retrieval.

For a local walkthrough, use the [separate local connection](/guides/local-recording-context). Hosted account retrieval and local screen-frame access are different data paths. If the agent cannot see a screenshot on your Mac, adding the hosted URL again will not grant filesystem access.

| Symptom | Check |
| --- | --- |
| Authorization repeats | Correct Eavesy account and completed client approval |
| Connected but intended recording absent | Account, recording completion, and retrieval scope |
| Local screenshot missing | Local file/image access or local walkthrough MCP |
| Answer has unsupported details | Source excerpt and surrounding passage |
