Your agent didn't see the call, the screenshot or the message you copied.
Eavesy keeps those as Markdown, and there are three ways to hand them over.

## Paste it

Copy a brief, a transcript or a note from the launcher or the web app, and
paste it into your agent's chat. Briefs are already split into a summary,
decisions and action items, so the agent spends less effort finding what
matters.

<Callout type="tip">
Add a short instruction with the paste, like "Here's the brief from my design
review. Turn the action items into a checklist."
</Callout>

## Point it at your folder

The Mac app writes every capture as plain files in `~/Eavesy/Recordings`. An
agent that can read files, like a coding agent in your terminal, can search
and read them directly. No account or API is needed.

```text
~/Eavesy/Recordings/2026-06-15 Meeting recording/
├── summary.md
├── transcript.md
├── notes.md
├── meeting.json
└── audio.m4a
```

Screenshots and clipboard captures sit in the same place as `screenshot.png`,
`image.png` or `note.md`. See [your files](/docs/session-folder-format) for
the full format.

You can also point your recordings folder at a notes vault, so captures show
up next to your other notes.

## Connect over MCP

Let the agent look things up itself. Add `https://mcp.eavesy.com` as a
connector, sign in to Eavesy, and approve it. The agent can then search your
recordings and dictations. Connections are read-only unless you allow writes.

```bash
claude mcp add --transport http eavesy https://mcp.eavesy.com
```

MCP reads from your account, so it only sees recordings that have synced. See
[Connect an agent over MCP](/docs/connect-mcp) for each client.

## Shape the brief for the agent

A coding agent wants file paths and TODOs. A research assistant wants findings
and open questions. Regenerate a brief with a built-in format, or make your own
[template](/docs/templates).
