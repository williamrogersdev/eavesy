Eavesy exists to solve one problem: your AI agent didn&rsquo;t see the
message, the screenshot, the call, or the hallway decision — so it&rsquo;s working
blind. Whatever you drop into Eavesy becomes context your agent can actually
use. There are three ways to hand it over: paste it, point at the files, or
connect over [MCP](/docs/connect-mcp).

## Paste the brief

The fastest path. After any recording, copy the Markdown brief and paste it into
Claude, Cursor, ChatGPT, or any agent. Because it&rsquo;s clean Markdown with a
TL;DR, decisions, and action items, the model gets the full picture in one shot —
no copy-pasting raw transcript and hoping it sorts it out.

<Callout type="tip">
Pair a paste with a prompt like *&ldquo;Here&rsquo;s the brief from my call with
the design team — draft the follow-up tasks as a checklist.&rdquo;* The structure
in the brief does the heavy lifting.
</Callout>

## Connect over MCP

Signed-in accounts can connect an MCP-capable agent to the hosted, read-only
server and let it search recordings and dictations itself. See
[Connect an agent over MCP](/docs/connect-mcp).

## Point an agent at the folder

With the Mac app, every recording is a folder of plain files on your disk
([the session folder format](/docs/session-folder-format)). That means an agent
with filesystem access can read them directly:

```text
~/Eavesy/Recordings/2026-06-15 Design review/
├── summary.md
├── transcript.md
├── notes.md
├── meeting.json
└── audio.m4a
```

Clipboard notes, pasted images, and screenshots are saved in the same folder
root with different files (`note.md`, `image.png`, or `screenshot.png`, plus
`capture.json`). Point a coding agent, a local assistant, or a script at your Eavesy directory and
it can search, summarize, and reason over everything you&rsquo;ve ever recorded —
no API, no export step.

## Shape the context with a template

Different agents want context shaped differently. A coding agent wants file
paths and explicit TODOs; a research assistant wants quotes and open questions.
Open a completed recording and choose a built-in coding, research, customer, or
meeting format before selecting **Regenerate**. You can also create reusable
[custom templates](/docs/templates) in **Settings** or edit the final Markdown
directly.

## Connect an agent over MCP

Agents that speak the [Model Context Protocol](https://modelcontextprotocol.io)
— Claude, Claude Code, Codex, Cursor and others — can use Eavesy directly. In
the web app, open **Settings → AI assistants (MCP)**, select **New URL**, and
add that URL to your agent as a remote MCP server. Treat it like a password:
anyone with it can read your sessions. Revoke it there at any time.

The server gives your agent these tools:

| Tool | What it does |
| --- | --- |
| `search_meetings` | Search meetings by title or transcript, with an excerpt for each match |
| `get_meeting` | Fetch one meeting with its summary and full transcript |
| `recent_meetings` | List your most recent meetings |
| `search_dictations` | Search your dictations |
| `get_action_items` | List action items from your meetings, open or completed |
| `send_to_my_devices` | Send text to your **Drop** inbox (see below) |

### Send a handoff to your other computers

`send_to_my_devices` puts text, up to 5 MB, straight into your **Drop** inbox,
and it appears right away on every device where you have Eavesy open. It
takes the `text` and an optional `title`, which becomes the first line. The
drop is labelled with your MCP connection&rsquo;s name and kept for 7 days.

It&rsquo;s built for the end of a long agent session: instead of copying a
handoff doc and messaging it to yourself, ask the agent to send it.

<Callout type="tip">
Try *&ldquo;Write a handoff doc for this session and send it to my
devices.&rdquo;* Then open the **Drop** button on your other computer and copy
it into the next session.
</Callout>

## Why this beats a raw transcript

- **Structured, not a wall of text** — decisions and actions are already
  extracted, so the model spends its context budget on reasoning, not parsing.
- **Markdown the model already understands** — headings and lists map cleanly to
  how LLMs read documents.
- **Yours, on disk** — no vendor API in the loop; the files are local and
  portable.
