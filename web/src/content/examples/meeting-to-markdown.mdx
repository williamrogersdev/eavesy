This teaching example uses a fictional three-line conversation. The downloadable transcript and brief are hand-authored examples, not customer data or a claim about a generated Eavesy result. They demonstrate the structure you can use with your own reviewed recording.

## Read the source

```text
00:01 You: We agreed to launch on Friday.
00:05 Them: The help page still needs a review.
00:09 You: We have not assigned an owner for that review yet.
```

The source establishes a launch decision and an unresolved review task. It does not establish a calendar date, a time zone, the remote speaker's name, or who will do the review. Do not fill those gaps from a plausible story.

## Write a compact note

The [sample brief](/resources/examples/launch-brief.md) preserves the decision and the missing information. It points back to the source passages. Open both Markdown files in any text editor to inspect the result; no Eavesy account is needed to use this example.

In a real Eavesy capture, sign in for the completed cloud brief, then review it against the transcript and audio. Local recording files remain in the capture folder. A processing placeholder should not be treated as a completed summary.

## Keep it in a notes vault

Copy the sample brief into an Obsidian vault or your usual project folder. Give the note a useful title and link it to the project. If you move a whole capture folder, preserve references to any source media you want to retain. JSON metadata remains a separate file; it does not automatically become YAML frontmatter.

## Carry uncertainty forward

An action list for this source can say “Help page review — owner unassigned.” It cannot assign that work to the speaker who mentioned it. A decision log can record “Friday” while stating that the exact date needs confirmation.

Try changing the example to include an explicit owner, then update only the fields the new source establishes. The goal is a reusable record that remains faithful to what was captured.
